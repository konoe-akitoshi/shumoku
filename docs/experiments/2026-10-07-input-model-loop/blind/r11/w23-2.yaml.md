```yaml
name: Server room rack
nodes:
  - id: rt-1
    type: router
  - id: sw-1
    type: switch
  - id: srv-1
    type: server
  - id: sw-2
    type: switch
  - id: pdu-1
links:
  - endpoints:
      - node: rt-1
        port: lan3
      - node: sw-1
        port: xe-0/2/3
    speed: 10G
    cable: mmf-om4
    length: 3m
  - endpoints:
      - node: sw-1
        port: ge-0/0/1
      - node: srv-1
        port: eth0
    speed: 1G
    cable: cat6
    length: 2m
  - endpoints:
      - node: sw-1
        port: xe-0/1/0
      - node: sw-2
        port: xe-0/1/0
    cable: dac
    length: 1m
  - endpoints:
      - node: rt-1
        port: power inlet
      - node: pdu-1
        port: outlet 4
    cable: power
  - endpoints:
      - node: sw-1
        port: power inlet
      - node: pdu-1
        port: outlet 5
    cable: power
  - endpoints:
      - node: srv-1
        port: power inlet
      - node: pdu-1
        port: outlet 6
    cable: power
```

1. The format does not have a field for the “10GBASE-SR” optical transceiver standard.
2. I added the rack name as the network name, inferred device types from the description, and represented the untyped PDU as a node. I treated power connections as links with `cable: power`; the format has no separate field for inlet/outlet roles.
3. The format does not say whether `cable` should capture a cable’s subtype (such as `mmf-om4`) or the broader medium, or how to record transceiver standards. It also does not specify whether port labels such as “power inlet” and “outlet 4” should be modeled as `port` values.
