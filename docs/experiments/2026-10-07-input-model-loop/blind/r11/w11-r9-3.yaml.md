1. The description says that the cluster restarts VMs on another host when a host fails. The format can record the redundancy set and that `db-1` runs on an unspecified member, but it cannot express the restart behavior. It also cannot express that `mon-1` is known only from the monitoring system.
2. I added a `server-room` routing domain to associate the stated VLAN segments and their connected nodes. The description does not explicitly name a routing domain or say that these networks share one routing table.
3. The format says a segment’s `addresses` map can use a redundancy set ID for a shared virtual address, but does not explicitly say whether that ID may also be used as the key when recording a VM’s address while its host is unknown. I used `host: prod` for `db-1`, which captures its known placement within the cluster.
