```yaml
groups:

    label: Server room
  - id: rack-1
    label: Rack
    parent: server-room

nodes:
  - id: rt-1
    type: router
    group: rack-1
  - id: sw-1
    type: switch
    group: rack-1
  - id: srv-1
    type: server
    group: rack-1
  - id: sw-2
    type: switch
    group: rack-1
  - id: pdu-1
    type: PDU
    group: rack-1

links:
  - endpoints:
      - node: rt-1
        port: lan3
      - node: sw-1
        port: xe-0/2/3
    speed: 10G
    description: 3 m 10GBASE-SR multimode fiber (OM4) cable
  - endpoints:
      - node: sw-1
        port: ge-0/0/1
      - node: srv-1
        port: eth0
    speed: 1G
    description: 2 m Cat6 copper cable
  - endpoints:
      - node: sw-1
        port: xe-0/1/0
      - node: sw-2
        port: xe-0/1/0
    speed: 10G
    description: 1 m 10G direct-attach copper cable (DAC)
  - endpoints:
      - node: rt-1
        port: power inlet
      - node: pdu-1
        port: "outlet 4"
    description: Power connection
  - endpoints:
      - node: sw-1
        port: power inlet
      - node: pdu-1
        port: "outlet 5"
    description: Power connection
  - endpoints:
      - node: srv-1
        port: power inlet
      - node: pdu-1
        port: "outlet 6"
    description: Power connection
```

1. The format cannot express cable length, cable category/fiber type, or connector/transceiver details as structured fields; I put them in link descriptions. It also cannot represent power connections as a distinct link type, so these are ordinary links.
2. I treated the rack and server room as nested groups, put all listed devices in the rack, and inferred that `sw-2` and `pdu-1` are also in that rack. I interpreted “at 10G” for the first link and the DAC link as link speed, and named the unnamed rack `rack-1`.
3. It is unclear whether `type` should describe a broad role such as `router` or `switch`, and whether port names like “power inlet” and “outlet 4” belong in `port` when the connection is not a data link.
