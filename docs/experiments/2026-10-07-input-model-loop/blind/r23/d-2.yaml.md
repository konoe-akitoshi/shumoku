```yaml
groups:
  - id: hq
    label: 本社
  - id: osaka
    label: 大阪支店

connections:
  - id: lag-sw1-sw2
    label: LAG
  - id: wan-hq-osaka
    label: 広域イーサネット
  - id: expressroute
    label: ExpressRoute
  - id: ipsec-backup
    label: バックアップ IPsec トンネル

nodes:
  - id: rt-1
    type: router
    group: hq
  - id: sw-1
    type: switch
    group: hq
  - id: sw-2
    type: switch
    group: hq
  - id: prn-1
    type: printer
    group: hq
  - id: rt-2
    type: router
    group: osaka
  - id: ergw
    type: gateway

links:
  - endpoints:
      - node: rt-1
        port: te1
      - node: sw-1
        port: te0/1
    speed: 10G

  - endpoints:
      - node: sw-1
        port: te0/47
      - node: sw-2
        port: te0/47
    speed: 10G
    connection: lag-sw1-sw2

  - endpoints:
      - node: sw-1
        port: te0/48
      - node: sw-2
        port: te0/48
    speed: 10G
    connection: lag-sw1-sw2

  - endpoints:
      - node: sw-2
        port: ge0/10
      - node: prn-1
    speed: 1G
    bandwidth: 100M

  - endpoints:
      - node: rt-1
        port: ge0
      - node: rt-2
        port: ge0
    speed: 1G
    bandwidth: 300M
    connection: wan-hq-osaka

  - endpoints:
      - node: rt-1
      - node: ergw
    bandwidth: 2G
    connection: expressroute
    assumed: true

  - endpoints:
      - node: rt-2
      - node: rt-1
    virtual: true
    connection: ipsec-backup
```

1. ExpressRoute の途中にある機器や経路は不明です。形式では経路不明を直接表せません。`assumed: true` はリンク自体の存在が未確認という意味なので、途中機器が不明なことの表現には使えません。
2. ノードの `type`、拠点のグループ分け、接続の名前を補いました。ExpressRoute の 2G は契約帯域として `bandwidth` に記し、ポート速度が書かれていないため `speed` は省略しました。説明にある回線の存在は確定しているので `assumed` は付けません。
3. `connection` が複数リンクをまとめる論理接続を表す一方、WAN や ExpressRoute のようにリンクが1本だけの場合にも使えるかが少し不明です。また、機器のポート速度とリンク速度が異なる場合、`speed` がどちらを示すかは明確ですが、ポートの対応速度自体を記すフィールドはありません。
