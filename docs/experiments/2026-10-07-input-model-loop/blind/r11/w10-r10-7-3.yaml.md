1. **Could not express:** The router’s separate guest routing table versus its main routing table; the schema can identify the guest routed network, but has no explicit routing-table or VRF attachment field. The AWS Transit Gateway’s attachment through both subnets is also not directly represented as an attachment; the schema can only show the gateway’s network membership and its presence in the subnets if those are listed.
2. **Guesses/additions:** I treated the server room and availability zones as groups, and VLANs and AWS subnets as segments. I used product paths and node types to capture the named vendors and AWS services. The two VPN tunnels are represented as parallel virtual links. I associated the router with both VLAN segments because its described links or VRF imply that presence, and put `fw-v` and `app-1` in the server-room group.
3. **Unclear:** Whether a `RoutedNetwork` represents a routing table/VRF as well as a cloud network, and how to represent a gateway attachment to a VPC through specific subnets. The format also does not specify a canonical vocabulary for `type`, `product`, or `software`.
