```yaml
name: 本社と大阪支店のネットワーク

groups:
  - id: hq
    label: 本社
  - id: osaka
    label: 大阪支店

connections:
  - id: carrier-wan
    label: 通信事業者の広域イーサネット
  - id: expressroute
    label: ExpressRoute
  - id: ipsec-backup
    label: バックアップ IPsec トンネル

nodes:
  - id: rt-1
    label: rt-1
    type: router
    group: hq
  - id: sw-1
    label: sw-1
    type: switch
    group: hq
  - id: sw-2
    label: sw-2
    type: switch
    group: hq
  - id: prn-1
    label: prn-1
    type: printer
    group: hq
  - id: rt-2
    label: rt-2
    type: router
    group: osaka
  - id: ergw
    label: Azure ExpressRoute ゲートウェイ
    type: gateway
    group: hq

links:
  - endpoints:
      - node: rt-1
        port: te1
      - node: sw-1
        port: te0/1
    speedMbps: 10000

  - endpoints:
      - node: sw-1
        port: te0/47
      - node: sw-2
        port: te0/47
    speedMbps: 10000
    connection: lag-sw1-sw2

  - endpoints:
      - node: sw-1
        port: te0/48
      - node: sw-2
        port: te0/48
    speedMbps: 10000
    connection: lag-sw1-sw2

  - endpoints:
      - node: sw-2
        port: ge0/10
      - node: prn-1
    speedMbps: 100

  - endpoints:
      - node: rt-1
        port: ge0
      - node: rt-2
        port: ge0
    speedMbps: 1000
    connection: carrier-wan
    description: 契約帯域 300M

  - endpoints:
      - node: rt-1
      - node: ergw
    speedMbps: 2000
    connection: expressroute
    virtual: true

  - endpoints:
      - node: rt-1
      - node: rt-2
    connection: ipsec-backup
    virtual: true
```


1. ExpressRoute の途中の機器が分からないことは、分からないまま表現しました。経路や中継機器を表す専用の情報はありません。
2. `type` の値（`router`、`switch`、`printer`、`gateway`）と、各ノードを本社・大阪支店に割り当てたことは補いました。ExpressRoute ゲートウェイを本社に置いたのも推測です。広域イーサネットの契約帯域は `description` に記しました。LAG と各論理接続の関連付けを示すため、接続 ID とラベルを付けました。
3. `connection` が複数リンクを論理的に束ねることは示せますが、LAG であることを専用に表すフィールドはありません。リンクの `speedMbps` が物理ポート速度か契約帯域か明確でないため、広域イーサネットでは両端の引き渡し速度を記し、契約帯域を `description` にしました。ポート対応速度（プリンタ接続の 1G）は、リンク速度と区別して表すフィールドがありません。
