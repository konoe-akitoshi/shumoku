```yaml
name: Server room

routingDomains:
  - id: server-room-vr
    label: Server room VRF

segments:
  - id: vlan10
    label: staff
    vlan: 10
    prefix: 192.168.1.0/24
    addresses:
      web-1: 192.168.1.20
  - id: vlan30
    label: database
    vlan: 30
    prefix: 192.168.3.0/24

redundancy:
  - id: prod
    label: prod
    nodes: [esx-1, esx-2, esx-3]

nodes:
  - id: core
    type: switch
  - id: esx-1
    type: virtualization-host
    product: vmware/esxi
  - id: esx-2
    type: virtualization-host
    product: vmware/esxi
  - id: esx-3
    type: virtualization-host
    product: vmware/esxi
  - id: web-1
    type: virtual-machine
    host: esx-1
  - id: db-1
    type: virtual-machine
    host: prod
  - id: mon-1
    type: virtual-machine
    address: 10.99.0.50

links:
  - endpoints:
      - node: core
      - node: esx-1
    speed: 25G
    segments: [vlan10, vlan30]
  - endpoints:
      - node: core
      - node: esx-2
    speed: 25G
    segments: [vlan10, vlan30]
  - endpoints:
      - node: core
      - node: esx-3
    speed: 25G
    segments: [vlan10, vlan30]
  - endpoints:
      - node: esx-1
      - segment: vlan10
    virtual: true
  - endpoints:
      - node: prod
      - segment: vlan30
    virtual: true
```

1. The vSphere HA restart behavior is not expressible; the format records cluster membership but not failover policy.
2. I guessed that the server room has a separate routing domain and that the core is a switch, the hosts are virtualization hosts, and the VMs are virtual machines. The format has no explicit VMware ESXi software field in this example; I used `product` for ESXi.
3. The VM’s port group attachment is represented as a virtual link to a segment. For `db-1`, the description does not identify a host, and `host: prod` expresses that it runs on one of the cluster nodes. The format does not define whether a redundancy ID may be used as a `host` value.
