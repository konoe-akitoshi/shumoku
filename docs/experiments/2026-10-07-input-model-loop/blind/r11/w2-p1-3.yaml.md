1. **Could not express:** The router’s separate main routing table and the fact it keeps a `guest` VRF; the format has no routing-table or VRF property on a node. The VPN’s two IPsec tunnels are represented as two parallel virtual links, but the format has no way to identify them as the two tunnels belonging to one VPN connection. The Transit Gateway’s attachment through both subnets is not explicitly represented.
2. **Guesses or additions:** I modeled the VPN connection as a separate node with two links to each endpoint, because the format describes links as node-to-node. I used `guest` as a routed network for VLAN 20, though it represents a VRF rather than a VPC-like network. I assigned generic node types and product paths where the description gave product information. I treated the VPN as virtual links and placed the AWS instances in their availability-zone groups.
3. **Unclear:** Whether a routed network can represent a VRF, and whether a node attached to a routed network should also be listed in one of its segments. The format also does not clarify how to encode a resource such as a VPN connection that consists of multiple tunnels while preserving the tunnel relationship.
