# 構成データモデルの再設計

入力の構成データは、開発の過程で必要なものと不要なものが混ざった。
これを、構造だけで意図が読める最小のモデルに作り直す。

## 進め方

先に理想のスキーマを文章で設計しない。実データで壊して直すループを回す。

1. 概念を削った最小のスキーマを型で書く
2. 既存の実データ（`examples/*.yaml`、実運用の図）を手で新形式に書き換える
3. 新形式から既存の処理系（layout / renderer）へ通す
4. 表せない・欠けるものが出たら、スキーマへ戻って直す
5. 収束するまで 2〜4 を繰り返し、固まってから後段を作り直す

## 決まりごと

- 概念は、実データで不足が出たときだけ足す。拡張性を先に用意しない
- 制約は型と構造で表す。不正な状態は表現できない形にし、文章の但し書きで補わない
- 説明が数行で済まないなら、まだ削れる。説明の長さは設計の不具合として扱う
- 構造だけを LLM に渡し、意図や後続の処理を読み取れるかで確かめる。既存コードは見せない
- 入力の層を固めるまで、source の統合・同期などの後段は詳細に設計しない

## ループに流す難しいデータ

すぐ対応する範囲ではない。新しいスキーマが黙って誤った形にしないかを確かめるのに使う。

- 三台以上が参加する共有セグメント
- Wi-Fi の AP と station
- trunk 上の VLAN、VRF
- シャーシと line card
- 配線とは別の向きを持つ依存関係
