2. I added node IDs for named external networks and route servers because links need endpoints. I placed JPIX and DIX-IE LAN addresses on `ncs5501se.kote`, JPNAP addresses on `ncs57c3`, and BBIX Tokyo addresses on `cisco8712` as inferred attachment points. I treated the optical connections from `ncs57c3` to `wxd` and `wxt-1` as parts of IOWN Open APN; the description does not specify ports, which wavelength carries JPNAP, or the exact path from those optical devices to JPNAP. The link entries with three endpoint items are invalid for the two-endpoint tuple; that format cannot represent one logical connection with both optical devices as separate endpoints, so those should be read as two links, each attached to the connection.
3. It is unclear how to represent an IX and its route server on a peering LAN without implying physical connections. I modeled each route server as a node connected to the relevant LAN, and modeled the named IXes as endpoint nodes for transit/IX reachability.
