The schema allows one `prefix` and segment addresses, but not separate IPv4 and IPv6 prefixes. I also could not faithfully place the given AS290 addresses: the format has no explicit association from an address to a routing domain, and assigning them to a border router would be a guess.
2. I treated transit providers and IXes as nodes and used inferred IDs where the description gave names but not identifiers. I also modeled KDDI's line and OCN as nodes, and represented the NTT optical network as a node. The JPNAP path through `wxd`/`wxt-1` is unclear, so the links from those devices to the optical network and onward to JPNAP are guesses; the YAML does not assert which wavelength carries JPNAP. I used endpoint links to represent carrier and IX paths, although exact connectivity details are not stated for every service.
3. It is unclear whether an IX, transit service, provider, carrier line, or peering LAN should be modeled as a node, segment, or connection. The format also has no direct way to express peer counts or the presence of route-server peering.
