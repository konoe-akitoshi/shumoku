```yaml
      web-1: 192.168.1.20
  - id: vlan-30
    label: database
    vlan: 30
    prefix: 192.168.3.0/24
    network: server-room

redundancy:
  - id: prod
    label: prod
    nodes: [esx-1, esx-2, esx-3]

nodes:
  - id: core
    type: switch
    network: server-room
  - id: esx-1
    type: virtualization-host
    product: vmware/esxi
    network: server-room
  - id: esx-2
    type: virtualization-host
    product: vmware/esxi
    network: server-room
  - id: esx-3
    type: virtualization-host
    product: vmware/esxi
    network: server-room
  - id: web-1
    type: virtual-machine
    host: esx-1
  - id: db-1
    type: virtual-machine
    host: prod
    segments: [vlan-30]
  - id: mon-1
    type: virtual-machine
    address: 10.99.0.50
    assumed: true

links:
  - endpoints: [{node: core}, {node: esx-1}]
    speed: 25G
    segments: [vlan-10, vlan-30]
  - endpoints: [{node: core}, {node: esx-2}]
    speed: 25G
    segments: [vlan-10, vlan-30]
  - endpoints: [{node: core}, {node: esx-3}]
    speed: 25G
    segments: [vlan-10, vlan-30]
```

1. The format has no explicit field for a VM network adapter or port group. `web-1`’s known VLAN membership and address are represented through the VLAN 10 segment; `db-1`’s known VLAN membership is represented with `segments`.
2. I added a `server-room` routed network and attached the core, hosts, and VLAN segments to it. The description does not identify a routed network or say the hosts/core are attached to one. I also used `type` labels for the devices and `vmware/esxi` as the hosts’ product path; those exact type names and product path are inferred.
3. `assumed` means believed to exist but unconfirmed. The description says `mon-1` is known from monitoring, so that flag does not fit; the format has no field for “known to exist, but placement and network are unknown.” The redundancy model also doesn’t say whether `prod` represents the HA cluster as a whole or only a placeholder for the unknown host when used as `host`.
