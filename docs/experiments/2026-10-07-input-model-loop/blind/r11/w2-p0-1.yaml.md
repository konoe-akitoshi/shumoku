1. The format cannot explicitly represent the router’s separate main routing table, the AP’s VLAN tag, VMware port groups, EC2/RDS deployment details beyond the product/software strings, or the fact that the VPN consists of two distinct tunnels. The tunnel pair is noted in the link description.
2. I treated `guest` as a routed network representing the VRF and used `main` for the VPC. I inferred product paths for AWS resources and software paths for ESXi and Amazon Linux. The Transit Gateway attachments are represented as links to subnet IDs because there is no attachment type in the format. I used `prod` as the host reference for `app-1`, following the stated uncertainty about which cluster host runs it.
3. It is unclear whether `Node.network` should be used for an AWS resource attached to a VPC when it is already in a subnet belonging to that VPC. I omitted `main` from `web-c` and `db-c` because their subnet membership already implies it. The format also does not specify a convention for product/software path names.
