## 不採用・比較用: 3つの固定・分断を見直す coupled-search

依頼: 「コミットしてから３つを解消する方法を考えて試してみてほしい」。
まず dependency-y と固定条件の棚卸しを **`e1094bd5`** に保存した。67テスト成功・変更ソースの
Biomeチェック成功。通常フックは既知の `bunx` 未検出 / ルートBiomeの `preset` 非対応で失敗し、
この保存コミットのみ `LEFTHOOK=0` を使用した。無関係なWebサイト変更は含めず、pushなし。
以下はその後の新しい試行であり、追加コミット・本番統合はしていない。

### 3つに対する変更と到達点

| 課題 | 今回の実装 | まだ言えないこと |
|---|---|---|
| 初期配置・順序への固定 | ノードXY・グループXY・ノード同士とグループ同士の位置交換を探索。初期位置への引力、同一Y、旧上下順、固定分離軸を使わない。構成データだけから作る初期配置でも実行 | 初期配置に左右されず同じ品質まで到達すること。有限探索ではまだ大きな差がある |
| 接続辺・境界点・配線の固定 | 四辺の選択、辺上の順序、境界点の辺上移動、他の配線を考慮する迂回候補、再配線の処理順を探索。旧端点・旧仮想レーンは読み込まない | 全ての辺・順列・自由空間内の曲がり点を網羅すること |
| 内部配置→枠→配線の一方向処理 | 候補ごとに必要帯と枠を整合させ、端点と経路を再計算。その**最終的に描かれる経路**の長さ・交差・重なりを評価して候補を採否判定 | 連続・離散変数を厳密に同時最適化した大域最適解。実装は全体評価つきの近傍探索 |

**固定を探索変数に戻すことと、良い最適解に到達することは別。前者を進めたが、後者には課題が残る。**

![保存地点と連成探索の比較](archive/tmp-test6-v8-coupled-search-comparison.png)

### 何を固定せず、何を守るか

- 実リンク・所属は入力JSONから再構築する。表示済みデータから読むのは機器の表示寸法・描画用情報。
  既存配置を開始点にする場合も、座標だけを候補の初期値とし、旧深さ・階層・経路・端点・仮想レーンは使わない。
- 根のIDと絶対座標は実験設定の引数。汎用処理内に `test:internet` を埋め込まない。
  根からのグラフ距離は実接続から再計算し、機器役割を上下関係の判定に使わない。
- 必須なのは根の固定、実機・サブグラフの必要帯の非重複、線と非接続ノードのクリアランス、
  枠内への所属、境界を通過すること、端点の物理的な収容。上下・左右どちらに分離するかは固定しない。
- 衝突修復は現在の矩形から最小の平行移動方向を毎回選び直す。軸や符号を初期配置から保持しない。
  さらに位置交換・大きな移動候補を持つため、修復方向が唯一の探索方向にはならない。
- サブグラフ寸法は現ノードの必要帯を含む範囲と、現在選ばれた境界辺の端点収容数から再計算する。
  旧幅・旧高さ・旧行間を下限にせず、固定の最大寸法も設けない。
- 端点側が変われば接続数の方向別配分が変わるため、必要帯・枠の寸法・衝突修復を再確認する。
  最終形が成立しない、または数値反復が予算内に収束しない候補は不採用にする。
- 配線は障害物矩形の角を候補とする可視グラフで求める。直接見通せる線も候補に含める。
  他の線との交差・共有区間を経路コストに含める別経路も試す。旧レーンの通過順や上下関係は保持しない。
- 一階層一行・上下順固定のための226本の水平区間は使わない。線間の交差・共有区間は
  評価項として扱い、交差まで絶対禁止する新しい制約は追加しない。

### 全候補に使う評価

```text
S = L / U + C + O / U + D
U = sqrt(実機の表示面積の平均)
L = 最終ポリラインの総長
C = 最終ポリラインの交差リンク対数
O = 最終ポリライン同士の共有区間の重なり長
D = Σ有向と解釈した実リンク [max(0, d - (Ychild - Yparent)) / d]²
d = 両ノード半高さの和 + 線ピッチ
```

上下方向は根からのグラフ距離が異なる実リンクにだけ評価を置き、同距離の辺には置かない。
これは望ましい読み方向についての**調整可能な評価**であり、子を上へ動かすことを禁止する条件ではない。
長さ・交差・共有区間・依存の重みは今回全て1。最良候補を保存しながら、途中では焼きなましで
悪化候補も許す。温度、候補数、乱数seedは計算予算・探索方法の設定であり、描画位置の制約ではない。
評価値が下がっても各指標が全て改善するとは限らない。

### 残している前提・モデル・探索範囲

- 表示寸法、四辺上で中央を基準に等間隔に分散する機器端点は、これまでの表示方針を継承。
- ノード・枠の基準面積比15%、線余白係数1.5、描画線幅、枠の見出し余白24/44pxも実験設定として継承。
  「数値設定がゼロになった」「唯一必然の評価式になった」とは言わない。
- 各候補内で端点間隔を満たすため順序付き一次元配置を解くが、その順序自体は探索で変更できる。
- **単純に全条件を減らした実装ではない点にも注意**: 今回は端点を角から線ピッチ分離し、
  機器辺の容量判定を `(端点数 + 1) × 線ピッチ <= 辺長` とした。旧版の `端点数 × 線ピッチ` より
  保守的な扱いで、必要最小限であることは証明していない。枠も実機本体だけでなく必要帯を含めて包む。
  これらは今回選んだ幾何モデルの前提であり、上下順固定などを撤去したことと区別して監査する。
- 曲がり点候補は障害物の角であり、任意の空き空間の全点・曲線を探索しているわけではない。
  端点の辺や順序も、今回の有限回数ですべてを列挙したわけではない。
- 修復は最大512回。これは不要な上下固定を戻す代わりではなく、収束しない候補を終了する数値予算。
  濃密な初期候補の棄却は探索の偏りになり得る。良い構成データ由来の初期解は引き続き重要。
- 構成由来の初期配置はランダム極座標版と、実接続のばね・動的な非重複修復で事前に整える版を比較。
  後者は初期値を作るための近似評価であり、最終採否には必ず実配線の共通評価を使う。
  初期化で得られた行・角度・位置・順序をその後の制約にしない。

## 再開基準 dependency-y: 同じYを制約にせず、依存関係から近いYになるか

依頼: 「最適化した結果同じようなY座標になるのが理想」「考えて試してみて」。
`distributed-ports-report.json` を開始点に、各実機と各横配線レーンに独立したY変数を与えた。
左右順・相対X・接続辺・端点の分散量はそのまま。**兄弟同士のY差を罰する項目、行Y変数、
元Yに戻す項目、全ノードへの階層順制約は入れていない。** `depth` は結果比較のラベルにのみ使用する。
この試行を新しい採用済み保存地点とは扱わず、旧図を上書きしない。コミット・本番変更なし。

![同一Y固定と独立Y最適化の比較](archive/tmp-test6-v8-dependency-y-comparison.png)

### 解いた問題と、まだ固定しているもの

各サブグラフについて、次の二次評価を線形の離隔条件のもとで同時に最小化する。

```text
E = Σ実リンク依存 ((Ychild − Yparent − d) / d)²
  + Σ配線接続区間 ((Yend + offsetEnd − Ystart − offsetStart) / s)²

d = 両ノードの半高さ + ノード枠線幅 + 親の下側必要帯 + 子の上側必要帯 + 線ピッチ
s = sqrt(区間のX差² + (その配線の始点ノード高さ + 線ピッチ)²)
```

- 依存の向きは Internet からの既存のグラフ距離 `rootDistance` で判定する。
  内部の全実リンクを使い、同距離の接続は上下依存にはしないが配線項には含める。機器役割は使わない。
- `d` は固定の行間ではなく、リンクごとの望ましい親子距離。逸脱可能な評価項。
  `s` による正規化も今回選んだモデルであり、依存関係だけから唯一決まる評価ではない。
- 必須条件は、X範囲が重なるノード必要帯同士、線レーンとノード、線レーン同士の非重複。
  不足空間を評価の重みと交換しない。上下どちらを通るか・重なるレーンの順序は開始配置から固定する。
- Internet の絶対位置は固定。孤立した自由成分には平行移動だけの基準を設ける処理があるが、
  今回のデータでは不要だった。通常のノードを初期Yへ引き戻す評価には使っていない。
- 実装は ADMM による凸二次問題の数値解。最大20,000反復、残差・更新量 `1e-7` 未満を要求。
  各群の条件・初期値・解・反復数をレポートに保存する。固定した順序内の解であって、
  ノード順・レーン順・接続辺まで探索した大域最適ではない。
- 従来の34個の「行内仮想通過枠」を固定点としては使わず、226個の実際の横配線区間を
  線ピッチ5.5pxの厚みを持つ独立Y変数として扱う。実機は89台のまま。
  全ての仮想区間が最終的な配線上に存在することを検証する。
- 枠はノードと線区間を包む寸法に再計算し、必要帯が重ならないようサブグラフ全体を平行移動する。
  幅上限・行間の初期値下限は追加しない。継承した左右下24px・上44pxの描画用余白は残る。
  内部は障害物回避経路を再構築し、外部は境界点間を再配線する。
- **境界点は局所最適化時には旧枠上で固定し、その後の枠変更で比例移動する。**
  したがって評価値は枠再計算前の局所モデルについての値であり、最終配線全体の最適値ではない。
  サブグラフ配置・端点・配線との反復的な同時最適化は未実施。

### 配置・配線の自由度を制限している固定ルール

- **開始配置が固定**: `virtual-rows-area-15-report.json` を指定して読み込む。
  生の構成データから全体を配置し直す処理ではなく、以前の配置判断を継承する。
- **起点IDが固定**: コードで `test:internet` を検索する。起点ノードの絶対位置を保持する。
- **実機の階層・左右順・サイズ・行内Xは維持**: 個別に上下へ逃がさず、行間を変える。
  一階層一行はユーザーの要望で維持している条件であり、不要な固定値と一括りにしない。
- **サブグラフ幅を再探索しない**: 開始時の幅を保持し、高さを必要な配線容量で増やす。
  固定の最大幅を追加したわけではないが、現在の処理には横方向へ広げ直す自由度がない。
- **行間を開始時より縮めない**: `max(開始時の行間, 必要容量)`。
  線が減って必要量が小さくなっても、開始配置にあった余白は下限として残る。
- **ノードの接続辺は選び直さない**: 既存の辺上で、相手の中心方向順・中央対称・等間隔に分散。
  同方向の並列リンクはID順。同時に接続辺や並び順の別解を探索する方式ではない。
- **辺容量不足はエラー**: `本数 × 間隔 > 辺の長さ` の場合、間隔を圧縮したり、
  ノードを拡大したり、他の辺へ振り分けたりはしない。
- **仮想通過枠・境界点の既存選択を保護**: 枠とともに位置は変わるが、
  通過先や境界辺の選び直しは行わない。
- **レーン割当は固定方式**: 横区間の左端順に、使用可能な最初のレーンへ割り当てる。
  交差数を評価してレーン順を最適化する処理はない。
- **競合区間の接続形状も固定方式**: レーンへの接続は「縦→横→縦」。
  競合しない区間は元の経路を保持する。自由な曲線や斜線の候補との比較はしていない。
- **サブグラフの分離も限定的**: 初期位置からX/Y方向に押し離す。
  一回の修復中は分離軸や各辺で観測した最大必要厚さを保持する。
  以前の極座標による配置そのものを再最適化する処理ではない。

## V8 追記: 中心基準の方向と、実際の接続点を分離

「中心の一点から出すのではなく、中心から考えるだけで始点は余白と同様に分散させる」に対応。
既存の四辺中央固定を外し、始点・終点の両方を分散した。`distributed-ports` として別保存。

- 接続辺の選択は従来の中心基準の結果を維持。その辺の中では、接続先ノードの中心方向で
  並べ、方向が同じ並列リンクはリンク ID で安定順序にする。位置変更前の中心を使う初期割当であり、
  最終グループ配置の変更後に全接続辺や端点順序を再探索するものではない。
- 本数を k、0 始まりの順番を i とし、辺中央からの位置を
  `offset = (i - (k - 1) / 2) × pitch` とする。1 本なら従来どおり中央。
- pitch は線レーンと共通の `線幅 + 2 × クリアランス × 線余白係数`。
  今回は 5.5px。別の固定ポート間隔を追加せず、線余白係数で追従する。
- ノード直近の同一直線部分も接続点の分散に合わせて移動させる。
  すぐ元の中央一点へ戻す処理は入れない。元の直線を分散後も安全に直線で結べる場合は維持する。
  仮想通過枠とサブグラフ境界点は勝手にずらさず、必要なら内部の可視グラフで実機を避ける。
- この新しい端点・直近配線を使って行間の占有区間とレーン容量を再計算する。
  固定した既存レーンへ表示上の端点だけを差し替える方式ではない。
- ノードのサイズ・階層・行内 X と左右順、Internet の絶対位置、ノード帯の計算式を維持。
  本数が増えて `k × pitch > 接続辺の長さ` となる入力はエラーにする。
  隠れた間隔圧縮・ノードのサイズ変更・別の辺への振り分けは行わない。今回の入力では余裕を持って収まった。

## V8 追記: 線自身が必要な通過領域を確保する

「ノードに所属グループの台数・線数を加算するのではなく、線自体が動的に余白を確保すべき」
という方針を実装。`virtual-rows-area-15` を入力に、旧成果物は残して `wire-channels` を生成した。
ノード側の基準面積比・自身の接続数による帯計算は変更せず、今回の差を線の容量に限定する。
グループ台数・総リンク数のノード余白への加算は入れていない。

### 今回の処理

1. 既存の内部配線を実機行の上端・下端で分割し、各行間（枠と最初／最後の行の間も含む）
   を通る部分を抽出する。各部分の始点・終点が作る横方向の区間を通過要求とする。
2. 横方向の占有範囲が重なる要求に別レーンを割り当てる。離れた区間はレーンを再利用する。
   区間の左端順に処理し、空いている最初のレーンへ入れる区間分割法。
   サブグラフの総線数ではなく、同じ場所で必要な同時通過容量を求める。
3. 1 レーンの幅は `線幅 + 2 × クリアランス = 1.6 + 2 × 1.3 = 4.2px`。
   行間の必要容量は `レーン数 × 4.2px`。新しい行間は `max(従来の行間, 必要容量)`。
   縦に行を横切る既存の仮想枠は、元から 1 本ごとの幅を横に足しているため増幅しない。
4. 行間だけを拡張する区分線形の Y 変換を使う。実機の行は平行移動だけで、
   ノードサイズ・階層・左右順・行内 X は保持する。Internet の絶対位置も保持。
   行を水平に保つため、ある X 位置で必要になった高さはその行間全体に適用される。
5. 占有範囲が競合する線は確保した水平レーンへ接続する。競合しない部分は元の経路形状を保ち、
   行間の伸びだけを反映する。実機のある行の中の経路も元の形状を保つ。
6. 枠も配線領域を含めて拡張し、必要余白の分離はグループ単位の平行移動で実行。
   境界点は従来の辺を保持して枠と一緒に変換し、外部経路はその境界点間で再計算する。
   今回、境界点の辺選択や配置全体の最適化をやり直してはいない。

本方式は内部行間の線容量を扱う。外部配線全体の太い通路を確保する実装ではない。
単なる余白の一括増量でもないが、レーンの容量だけでは出入口の交差までは解消できない。

## V8 追記: 接続数と辺ごとの集中を反映した余白帯

`area-halo` の結果を開始点に、同じ基準面積比 10% で追加実験。
ノードは接続リンクの端点数、サブグラフは境界プロット点数を k として、
外周余白の面積を **本体面積 × 0.1 × sqrt(1 + k)** とする。
本体は枠線を含む外接矩形。内部だけで完結するリンクはサブグラフの k に含めない。
並列リンクはそれぞれ数え、同じ四辺中央の接続点を共有していてもまとめない。

各候補の再配線後に、実際のノード端点と境界点から辺ごとの本数を数え直す。
接続していない辺にも前回の等厚の基本余白を保持し、**接続数で増えた面積だけ**を
辺ごとの `本数 / 辺の長さ` に応じた厚さで配分する。角の面積も含めて総面積を一致させる。

```text
目標余白面積 B = r A sqrt(1 + k)
基本余白の厚さ = d0（従来の面積比 r から算出）
各辺の厚さ = d0 + t × その辺の本数 / その辺の長さ
```

t は、拡張後の矩形面積 − 枠線込み本体面積 = B を満たす正の解。
接続のない辺の厚さは d0 のまま。サイズ拡縮に相似追従し、役割名による重み付けはしない。

## V8 追記: 面積比による外周の余白帯

`elastic-frames` の結果を開始点として、ノード同士とサブグラフ同士の接近を評価に追加。
以前の出力は上書きせず、`area-halo` として保存する。

ユーザーの面積ベースの定義を採用。比率の指定はなかったため、試験値 **10%** を採用した。
高さの何%でも、一定 px の最小間隔でもない。
枠線を含む外接矩形の幅を W、高さを H とし、その外側に付ける余白帯の厚さ d を求める。

```text
(W + 2d)(H + 2d) − WH = r WH
d = r WH / (sqrt((W + H)² + 4rWH) + W + H)
```

W/H はノード・グループごとに実寸から求める。グループが拡縮するたびに d を再計算。
同じ面積なら細長い形ほど薄くなる。描画全体を一様に拡大すれば厚さも同じ倍率で拡大する。
丸角の厳密な面積ではなく、枠線を含む外接矩形によるモデル。

- 本体同士の非重複条件は従来どおり。余白帯は **ソフトな評価** であり、強制的に離す条件ではない。
- 余白帯を含めて拡張した矩形同士の重なり面積を、両者の小さい方の余白帯面積で割り、
  その二乗を組ごとに加算する。余白帯に相手の本体が侵入する場合も評価対象。
  純粋な「帯と帯」だけの交差では、辺同士が接触した状態を適切に罰せないため。
- ノード間／グループ間のペナルティをそれぞれ開始時の値（下限 1）で規格化し、
  既存の線長・交差・重なり・侵入深さと等重みで加算する。ノード貫通件数最優先は維持。
- 帯の重なりをちょうど解消する移動量も幾何から生成する。全量・半量を候補とし、
  枠・周辺グループ・境界点・外部経路を更新した結果で採否を決める。
- 比率、評価の等重み、探索上限 8 周という設定は残る。完全自動・大域最適ではない。
  タイトル用などの既存の内側余白と、境界点の分散処理も変更していない。

## 現在のアルゴリズム

### 構成から決めるもの

1. `test:internet` をユーザー指定の起点として扱う。
2. 全リンクを無向 BFS でたどり、ノードごとの最短接続段数を求める。
3. 各グループ内で段数順に配置。同じ段数は一行。存在しない段数の空行は作らない。
4. 内部の上流隣接ノードは複数でも `parentNodes` に保持。木にするためにリンクを削除しない。
5. ノード幅・行幅・行高・タイトルと描画余白から枠を算出。役割ラベルは表示だけに使う。

### 探索するもの

- サブグラフ中心の距離・角度、角度の入れ替え、接続グループ群の一括移動、ランダム再配置。
- 同じ内部階層の左右順。今回の内部候補は全グループ合計 265 通り、最大 48 通り/グループ。
- 実ノードから相手ノードへ向かう方向に基づく境界端点を再計算し、内部順序と最大 3 回交互更新。
- 高速探索では外部端点間を直線で評価。64 周の探索で得た候補を、実際に描画する外部経路で再評価。
- 最新実行は 21,078 候補を提案、配置可能な 5,703 候補を評価し、最終候補 7 件を外部経路で比較。

### 評価関数

外部＋内部の交差、内部線の無関係ノード貫通、内部線の同一直線上の重なり、全接続経路長の二乗和。
各項を以前の Internet 起点図の値で規格化して加算する。件数の分母は最低 1。
枠拡大直後の大きな初期余白を分母にすると長い配線が軽く評価されるため、比較基準を固定した。

内部線はノードの表示枠で切り取った直線と、ノードから境界までの線を計測。
外部の交差はリンク対単位で数え、共通の実ノードを持つリンク対は除外する。
内部と外部の交差は別領域のイベントとして加算する。外部の同一路線の重なりは未評価。

### 維持している条件 / 外した条件

- 維持: Internet を含む起点グループは最上部、内部は一階層一行、枠・ノードは非重複、全リンクを保持。
- 維持: ノード間隔 18px、内部段間隔 20px、タイトル等の描画余白、外部経路の片側 10px クリアランス。
  枠同士の分離判定は約 20px。これらは今回変更していない。
- **撤去: 非起点グループ同士の、枠全体に対する上下順序。** 接続していても横並びや逆の高さを許す。
- 追加していない: 枠の最大サイズ、兄弟の折り返し、固定リング・角度セクター、役割別 tier。
- グループの所属、内部階層・サイズ、規格化の基準は直前の実験から維持。内部の左右順は再探索される。

## 検証と残課題

保存先で 15 テスト、687 アサーションを実行する構成。

最新レポートの必須幾何チェックはすべて 0。ただし内部の線による貫通は評価対象であって禁止条件ではない。

残課題:

- BFS の段数は実際の上流方向ではない。冗長・迂回接続をどう意味づけるか。

- 高速な直線評価と、最終の迂回経路評価に差がある。候補の絞り込みで良い配置を落としていないか。
- 3 回の内部・端点交互更新、初期配置依存、有限の大域移動。最適解の保証はない。
- 同一の探索予算で制約あり/なしを比較する対照実験は未実施。
- 起点グループだけは枠全体を最上部に置く条件が残る。Internet ノードだけの固定とは異なる。
- 本番規模への計算量評価、UI の起点選択、本番エンジンへの統合は未実施。
