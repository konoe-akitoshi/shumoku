## トポロジーの作成

1. サイドバーの **Topologies** をクリック
2. **Add Topology** をクリック
3. 名前を入力して保存
4. 開いた **Sources** 画面で、Manual ソースまたはプラグインのデータソースを追加

## 手で書く

Manual ソースの編集画面で、構成を YAML で書けます。YAML には構成（ノード・リンク・グループ・セグメントなど）だけを書きます。プラグインが見つけた識別情報や、図の位置・色などは YAML に出ず、そのまま保たれます。

```yaml
name: My Network
groups:
  - id: dc
    label: DC
nodes:
  - id: router1
    label: Core Router
    type: router
    product: juniper/mx204
    group: dc
  - id: switch1
    label: Distribution Switch
    type: l2-switch
    group: dc
links:
  - endpoints: [{ node: router1, port: ge-0/0/0 }, { node: switch1, port: ge-0/0/1 }]
    speed: 10G
```

- リンクは `endpoints` に両端を書きます。ポートが分からなければ省きます。端に挿さっているもの（ケージとトランシーバ）は端の `plug` に書きます。
- 速度は `speed` に `1G`・`10G`・`2.5G` のように単位付きで書きます。
- ケーブルは `cable` に種別（`cat6`・`om4`・`smf` など）を書きます。プロジェクトの機材ライブラリの製品を指すときは `cable: { type: om4, productId: … }` の形で書きます。
- ノードのポートは、名前以上のことが分かっているとき（インターフェース名・速度・コネクタ・PoE など）やリンクの付いていないポートがあるときに `ports` に書きます。リンクの端はポートを `name` で指します。
- 配線が通る受動的な点（壁コンセント・立ち上がり（EPS）・パッチパネル）は `terminations` に書き、リンクは通る順に `via` で指します。座標は書けません。
- グループは `groups` の中に入れ子で書き、ノードは `group` で属するグループを指します。
- 書いていないことは「無い」ではなく「分からない」として扱われます。

旧形式（`from` / `to`、`subgraphs`、`file:` によるファイル分割）は読めません。書き直してください。

## 図の描かれ方

図の座標や上下は書けません。上下は入力から決まります。YAML にも画面にも、上下を測る起点（境界）を指定する欄はありません。

- 境界（外側との接点）は次の順で決まり、前の段階で見つかれば後ろは使われません。
  1. 描画設定の `boundary`（`drawing.settings.boundary`）。YAML や画面からは書けず、プログラムが `NetworkModel` の描画層に入れたときだけ使われます。
  2. `type: internet`・`type: external`・`type: cloud` のノード、およびリンクが届いているルーティングドメイン。
  3. 1〜2 のどれも届いていない、ケーブル（`virtual: true` でないリンク）でつながったまとまりごとに、上端を 1 か所推測します。種類の序列（ルーター > ファイアウォール・VPN・CPE > L3 スイッチ・ロードバランサー > L2 スイッチ > AP）で最初に見つかる段のノード、無ければ一番速いリンクの先のノード、それも無ければすべてのノードを候補にし、そのうちつながりの中心にあるものが上端です。トンネルだけでつながる拠点は、別のまとまりとして自分の上端を持ちます。他のまとまりに境界があっても、このまとまりごとの推測は行われます。1 台だけのノードには何も付きません。物理リンクと仮想リンクの両方が付いているノード（VM を持つハイパーバイザなど）を、それだけで上端にすることはありません。
  推測は簡易です。上下を正しく描きたいときは、外側（インターネット・ISP・クラウド）を `type: internet`・`type: external`・`type: cloud` のノードとして書き、内側のノードとリンクでつないでください。NetBox から取り込むと、回線とプロバイダは `external` のノードになります。
- 境界から同じ距離にある、直接つながった 2 台は、機器の種類の序列（外部 > ルーター > ファイアウォール・VPN・CPE > L3 スイッチ・ロードバランサー > L2 スイッチ > AP > サーバー）で上下に描きます。種類で区別がつかない 2 台（同じ段、または種類の書かれていないノード）だけが横に並び、横の線で結ばれます。冗長構成（`redundancy`）の機器は、これまでどおり 1 つの枠の中に横に並びます。
- 線は直角と 45 度の線分で描かれ、角は円弧で丸められます。矢印・スプライン・二重線は廃止されました。仮想リンクは破線、見込みのリンクは点線で描かれます。線の太さは `speed` から決まり、速度が 1 桁上がるごとに一定の幅ずつ太くなります（1G で 4.5、10G で 6、100G で 7.5。速度の分からない線は、分かっている線の真ん中の太さ）。リンクに `speed` も規格も書かれていないときは、両端のポートの `speed` のうち遅いほう（片方だけ分かればそちら）が使われます。SNMP で機器を読み取ると、ポートの速度（ifHighSpeed、無ければ ifSpeed）も取り込まれます。VLAN を 1 つだけ運ぶ線は、その VLAN の色で描かれます（VLAN の番号順に、1 つの図の中で別々の色）。色はどれも背景に対してコントラスト比 3:1 以上で、見分けられる数（ライト 7、ダーク 9）を超える VLAN がある図では、VLAN で色を付けません。複数の VLAN を運ぶ線（トランク）と VLAN の無い線は、普通の線の色です。どの VLAN を運ぶかは、線の文字に出ます。
- ポート名は、機器の CLI が一覧表示で使う略記で描かれます（`TenGigabitEthernet1/0/1` は `Te1/0/1`、`Ethernet1/49` は `Et1/49`）。保存されているポート名は変わらず、ポートにカーソルを合わせると完全名が出ます。略記すると同じ表示になる名前が 1 台の中にあるときは、その名前だけ完全名のままです。1 辺に 3 本以上のポートがあって名前が長く並ぶときは、その辺の名前の共通する先頭部分（`Te1/0/` など）を辺の端に太字の札で 1 度だけ書き、各ポートの札には残りだけを書きます。それでも幅が足りない上下の辺では札を 2 段に互い違いに並べ、最後は名前の先頭を `…` で省きます（末尾が残り、辺の中で同じ表示にならない長さまで）。左右の辺の札は 14 文字ぶんまでです。
- 入れ子のグループは枠で囲まれ、図全体を 1 度に配置して 1 枚にまとめて描かれます。グループの中だけを先に配置することはないので、グループをまたぐ線もまっすぐ引かれます。枠を別シートに分ける機能（`file:` / `pins`）は廃止されました。
- グループの背景・枠・見出しの色は、描画が決めます。各グループの id から、テーマの 6 色のうち 1 色が選ばれ、深くなるほど 1 段ずつ背景から離れた濃さで描かれます。同じ id のグループは、どの図でも、ライトでもダークでも同じ色の系統になります。別々のグループが同じ色になることもあります。グループごとに色を選ぶ機能はありません。どの色・どの深さでもライトとダークの両方で、見出しの文字は 4.5:1、線・機器の縁・ポートは 3:1 以上のコントラスト比を保ち、グループの縁は機器の縁より控えめです。塗りはごく淡く、トラフィックの利用率や機器の状態の色は、グループの上でも背景の上で持つコントラストの 83% 以上を保ちます（ダークではむしろ上がります）。以前の図に保存されていたグループの色は読み込まれません。
- 機器の形と枠、線の色・太さ・破線も、何が描かれているかだけで決まります。機器はすべて角丸の四角で描かれ、枠はテーマの色です。線は VLAN を 1 つだけ運ぶならその VLAN の色・それ以外はテーマの色、太さは速度、破線は仮想リンク・点線は見込みのリンクです。機器や線ごとに形・色・太さを指定する機能はなく、以前の図に保存されていた指定も読み込まれません。
- ライブ表示の色（線の利用率、機器の状態の枠、監視状態のバッジ）は、ライトとダークでそれぞれ決めてあり、テーマを切り替えると追従します。線の色は背景に対して 3.6:1 以上、状態の枠とバッジは機器の枠と背景の両方に対して 3:1 以上です。利用率は 0%（データなし）・25% 以下・50% 以下・75% 以下・90% 以下・90% 超の 6 段で、凡例はこの段階どおりに表示されます。流れる点は線と同じ色相の明るい色で描かれ、動きを減らす設定では向きごとの利用率の色で塗られます。
- 中にグループを持たないグループは、その中だけで上下を決めて小さくまとめて描かれ、外からは 1 つの箱として並びます。中にグループを持つグループ（拠点など）は、図全体で揃った段に並びます。1 台のスイッチに 7 台以上の端末がつながるときは、端末を 1 行 5 台までに折り返し、スイッチの下にまとめて並べます。
- 拠点などのグループを別のグループの下にまとめて積むのは、そのグループへ入る線がすべて相手を通るとき（支社が本社にだけぶら下がるとき）か、積まなくても入口がすでに相手より下にあるときだけです。回線事業者などから直接入る道を持つ拠点は、別の拠点との間に線が 1 本あっても、その拠点の下には積まれません。1 つの箱にまとめて描かれるグループの奥の機器に外から線がつながっても、箱全体は下がりません。
- `host:` を書いたノード（VM など）は、その上で動くホストの箱の中に描かれます。ホストのカードが箱の見出しになり、VM は台数に応じて折り返して並びます。ホストのポートとリンクは箱の外周に付きます。`host:` にクラスタ（`redundancy` の ID）を書いた VM は、クラスタの枠の中にクラスタのノードと一緒に描かれます。ホストと違う `group:` を書いたノードは、その場所に描かれます。
- トポロジーの **Settings** > **Display** では **Hide Disconnected Nodes**（ソースを統合した後にリンクが 1 本もないノードを、例外なく隠す）だけを切り替えられます。この設定を適用するのはサーバーだけです。線の形式（エッジスタイル・スプライン）の設定は廃止されました。
- 図の移動: ホイールとトラックパッドの二本指操作は図をスクロール（パン）、ピンチと Ctrl/⌘＋ホイールはカーソル位置へズーム、Shift＋ホイールは横スクロール、Alt＋ホイールはスクロールとズームの逆です。マウスかトラックパッドかは推測しません（ブラウザでは確実に区別できないため）。**Settings** > **Display** の **Mouse Wheel** を **Zoom** にすると、素のホイールでズームします。この設定はブラウザごとに保存され、詳細ページと共有ページの図に効きます。ダッシュボードの図では、素のホイールはページのスクロールに使われ（図の上で「Ctrl + scroll to zoom」と表示）、ズームは Ctrl/⌘＋ホイールかピンチです。中ボタン・Alt＋左・Space＋左のドラッグでパンでき、詳細ページと共有ページでは左ドラッグでもパンします（4 px 未満ならクリック）。裏で図が描き直されても、見ている場所はそのままです。

### SpaceMouse

3Dconnexion の SpaceMouse で、マウスと併用して図をパン・ズームできます（詳細ページ・ダッシュボード・共有ページ）。キャップを横に押すとパン、引き上げる / 押し込むとズーム（中心はカーソル、図の外なら画面の中心）、Fit ボタンで全体表示、Shift ボタンを押している間はゆっくり動きます。ダッシュボードでは、カーソルが乗っている図が動きます。

- 必要なもの: Chrome か Edge（WebHID）、**HTTPS で開いたページ**（または localhost）。HTTP で開いていると、ブラウザが WebHID を無効にするので使えません（右下のボタンがそう表示します）。サーバーを HTTPS で公開する方法は[インストール](./installation.ja.mdx)の「リバースプロキシと HTTPS」を参照してください。
- つなぎ方: 図の右下のジョイスティックのボタン（ダッシュボードではウィジェットにマウスを乗せると出ます）を押し、機器を選びます。次からは自動でつながります。シリアル番号を持たない機種（SpaceExplorer など）は、抜くとブラウザの許可が消えるので、挿し直したらもう一度ボタンで選びます。
- Linux: 機器を読むには hidraw の権限が要ります。次の udev ルールを置き、`sudo udevadm control --reload && sudo udevadm trigger` で反映します。spacenavd は止めなくて構いません。
```text
# /etc/udev/rules.d/70-spacemouse.rules
KERNEL=="hidraw*", ATTRS{idVendor}=="256f", TAG+="uaccess"
KERNEL=="hidraw*", ATTRS{idVendor}=="046d", ATTRS{idProduct}=="c603|c605|c606|c621|c623|c625|c626|c627|c628|c629|c62b", TAG+="uaccess"
```
- Windows / macOS: 3Dconnexion のドライバ（3DxWare）が機器を押さえていると、入力が届かないことがあります。
- ボタンは SpaceMouse Pro 系・SpaceExplorer・2 ボタンの機種（SpaceNavigator、Compact など）に対応します。それ以外の機種ではキャップだけが効きます。
- 軸の向きと速さは、このブラウザで変えられます（開発者ツールのコンソールで）: `localStorage['shumoku.spacemouse.invert'] = 'x,y,z'`（反転したい軸）、`localStorage['shumoku.spacemouse.speed'] = '1.5'`（速さの倍率）。再読み込みで反映されます。

## データソースの紐付け

トポロジーの **Settings** タブで:

1. **Metrics Source**（Zabbix または Prometheus）を追加 — リアルタイムのリンク使用率・ノード状態を取得
2. **Topology Source**（NetBox）を追加 — トポロジーデータの自動生成・マージ
3. **Node Mapping** を設定 — トポロジーのノードと監視対象ホストを関連付け

## 共有

トポロジーの **Share** ボタンをクリックすると公開リンクを生成できます。リンクを持つ誰でもログインなしでトポロジーを閲覧できます。

アクセスを取り消すには、トポロジー設定で共有トークンを削除します。

## デバイスを直接読む（SNMP）

プラグインが「そこに機器がいる」と見つけただけの機器は、中身（ポート・機種・LLDP でつながる隣の機器）が分かりません。**デバイス**画面は、機器に直接つないでそれを読む設定をまとめて扱います。

- **認証情報**: 機器を読むための SNMP コミュニティなどに名前を付けたものです。ネットワークそのものの事実なので、サーバー全体で1つ持ち、変更も1回で済みます。コミュニティは一度入力すると表示されず、変更するときは新しい値を入れます（空欄のままなら今の値を保ちます）。**認証情報の作成・編集・削除・応答確認は管理者だけ**ができます。一般のユーザーは、そのトポロジーが使っている認証情報の名前と使用状況を見て、機器に割り当てることができます。
- **使うトポロジー**: 認証情報は、**使うトポロジー** に選んだトポロジーでだけ試されます。1台のサーバーで別々のネットワーク（顧客や会場ごとなど）を扱っても、ある拠点のコミュニティが別の拠点の機器に送られることはありません。同じネットワークを複数の図で見せるときは、それぞれの図を選びます。同じ機器が複数のトポロジーに入っていると、トポロジーごとに別々に読むため、問い合わせは重複します。
- **応答を確認**: 保存する前に、トポロジーの機器から最大10台を選んで SNMP の問い合わせを送り、何台が応答したかを確かめます。保存も機器への割り当ても行いません。
- **読み取る**: 認証情報を用意して **読み取る** を押すと、認証情報をまだ持たない機器に、そのトポロジーが使う認証情報を順に1回ずつ試します。応答したものがその機器に記録され、続けて機器の中身を読みます。誰も応答しない機器（PC・プリンタなど）は「応答なし」になり、認証情報の値を変えるか、使う認証情報を追加するまで再試行されません。以前は読めたのに読めなくなった機器も、認証情報が変わったあと、**読み取る** で他の認証情報を試します（どれも応答しなければそのままです）。
- **送信前の確認**: 試行は実際の機器に SNMP の問い合わせを送ります。押すと、対象の台数と最大の問い合わせ件数を示して確認します。送りたくない機器は、先に **対象外** にしてください。
- **例外だけを見る**: 一覧は結果ごとに分かれます。「読めなくなった」「一部だけ読めた」「未確認」「未取得」は最初から開き、「読めている」「応答なし」などは閉じています。機器を開くと、失敗の理由、認証情報の変更（自動で選ばれたものも人が上書きできます）、対象外への切り替え、その機器だけの読み取りができます。

認証情報を持つ機器だけが、中身まで読まれます。Sync や定期実行では SNMP を送らず、**読み取る** を押したときだけ読みます。読み取った結果は、Sync や Rebuild を行っても消えずに残ります。

読み取りは機器の表示名を書き換えません。機器が名乗る名前は sysName として記録され、誰も表示名を付けていない機器だけ、その名前（LLDP で隣の機器が報告した名前、アドレス、シャーシ ID、MAC の順）で表示されます。

読み取った機器は、そのアドレスで応答して自分のシャーシ ID と sysName を名乗ったことになります。これは機器自身の申告なので、そのアドレスで機器を知っているソース（NetBox や Zabbix など）と、シャーシ ID で知っているソース（AP の上流スイッチを報告する無線コントローラーなど）が別々の機器として扱っていた場合も、読み取りで1台にまとまります。まとまった機器の認証情報と読み取りの状態は、そのまま引き継がれます。ただし、そのアドレスの記録が別の sysName やシャーシ ID を持っている場合（アドレスが別の機器に付け替えられた場合など）は、まとめません。

## エクスポート

トポロジービューアの **Export** から、図全体を SVG または 2 倍解像度の PNG
としてダウンロードできます。単体で動作するインタラクティブ HTML も出力できます。
Server のエクスポートは、ビューアおよび CLI と同じ描画エンジンとレンダラーを使用します。
階層シートは廃止され、入れ子のグループは 1 枚にまとめて描かれます。
