1. The format has no field for the commercial relationship with AS64510 or AS64540, or for recording that there is no session with AS64530.
2. I used `cable: cable` because the cable type is unspecified. I represented the transit router and the routers for AS64520, AS64530, and AS64540 as unnamed or generic nodes; the format has no AS-only endpoint. The AS64540 link is marked `virtual: true` to avoid implying a physical path, though the description does not say that it is virtual.
3. It is unclear whether `virtual` is appropriate for the AS64540 session: the path is unknown, but the link may still use a physical cable. The format also does not specify how to represent an eBGP session that overlays a physical link, as with AS64510, or whether an exchange peering LAN should be modeled as a `Segment`.
