The format can record that the hosts are a redundancy set and that `db-1` runs on that set, but it cannot express the restart behavior or identify the set specifically as a vSphere HA cluster.
2. I used `server-room` as a group ID, and chose labels and node types for readability. I represented the VM adapters as virtual links to their segments because the format allows a segment endpoint when the other side is a shared network.
3. It is unclear whether a redundancy set represents hosts that stand in for one another, as the type comment says, or can also represent a cluster that hosts VMs across its members. The `host` field explicitly permits a redundancy-set ID, so I used `prod` for `db-1`.
