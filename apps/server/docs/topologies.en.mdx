## Creating a Topology

1. Navigate to **Topologies** in the sidebar
2. Click **Add Topology**
3. Enter a name and save
4. On the **Sources** screen that opens, add a Manual source or a plugin data source

## Writing It by Hand

In a Manual source's editor, write the configuration as YAML. The YAML holds the configuration only (nodes, links, groups, segments, ...). Identity found by plugins and the drawing's positions and colours are not shown in it and are kept as they are.

```yaml
name: My Network
groups:
  - id: dc
    label: DC
nodes:
  - id: router1
    label: Core Router
    type: router
    product: juniper/mx204
    group: dc
  - id: switch1
    label: Distribution Switch
    type: l2-switch
    group: dc
links:
  - endpoints: [{ node: router1, port: ge-0/0/0 }, { node: switch1, port: ge-0/0/1 }]
    speed: 10G
```

- A link lists its two ends in `endpoints`. Leave out a port that is not known. What is plugged in at an end (the cage and the transceiver) goes in the end's `plug`.
- Write a speed with its unit, such as `1G`, `10G` or `2.5G`.
- A cable is written by its type in `cable` (`cat6`, `om4`, `smf`, …); to name a product in the project's library, write `cable: { type: om4, productId: … }`.
- A node's ports go in `ports` when more than their names is known (interface name, speed, connectors, PoE, …) or when the node has ports no link uses. A link end names a port by its `name`.
- The passive points a cable runs through (wall outlets, risers (EPS), patch panels) are listed in `terminations`; a link names the ones it passes, in order, in `via`. Coordinates cannot be written.
- Groups are written nested under `groups`; a node names its group with `group`.
- Anything not written is unknown, not absent.

The older format (`from` / `to`, `subgraphs`, files split with `file:`) is not read; rewrite it.

## How the diagram is drawn

There is nowhere to write coordinates or which way is up. Up and down come from the input. Neither the YAML nor the UI has a field that names where they are measured from (the boundary).

- The boundary (where the network meets what lies beyond it) is decided in this order; an earlier step wins and the later ones are not used.
  1. The drawing setting `boundary` (`drawing.settings.boundary`). The YAML and the UI cannot set it; it is used only when a program puts it in the drawing layer of a `NetworkModel`.
  2. `type: external` and `type: cloud` nodes, and the routing domains that links reach. `type: internet` is not included.
  3. When step 2 finds none, nodes that have both a cable and a virtual link (`virtual: true`).
  4. For each connected part that none of 1-3 reaches, a guessed upstream: by type (router, firewall, VPN and CPE, then L3 switch and load balancer, then L2 switch, then access point), then the node(s) ending the fastest link, and failing those the most central node. The guess is made per part, also when other parts have a boundary. A lone node gets nothing.
  The guess is plain. When up and down matter, write what lies beyond the network (the Internet, an ISP, a cloud) as `type: external` or `type: cloud` nodes linked to the inside. From NetBox, circuits and providers come in as `external` nodes.
- Lines are drawn as right-angle and 45-degree segments, with corners rounded by arcs. Arrows, splines and double lines are gone. A virtual link is dashed and an assumed one dotted; the line's width follows `speed`. A line carrying a single VLAN is drawn in that VLAN's colour (taken in VLAN-id order, distinct within one diagram, each at least 3:1 against the background; a diagram with more such VLANs than can be told apart, 7 in the light theme and 9 in the dark, colours none); a line carrying several VLANs (a trunk) or none is drawn in the plain line colour, and its caption lists what it carries.
- Nested groups are drawn as frames on one page. Splitting a group into its own sheet (`file:` / `pins`) is gone.
- A node with `host:` (a VM, say) is drawn inside the box of the host it runs on: the host's card heads the box, and the VMs wrap in rows below it. The host's ports and links sit on the box's edge. A VM whose `host:` names a cluster (a `redundancy` id) is drawn in the cluster's frame with the cluster's nodes. A node that names a `group:` other than its host's is drawn there.
- **Settings** > **Display** keeps one switch, **Hide Disconnected Nodes**, which hides every node with no links after the sources are merged, with no exemption. Only the Server applies it. The edge style and spline settings are gone.
- Moving the diagram: a wheel and a trackpad's two fingers scroll (pan) the diagram, and a pinch or Ctrl/⌘ + wheel zooms at the cursor; Shift + wheel scrolls sideways, and Alt + wheel swaps scrolling and zooming. Whether the input is a mouse or a trackpad is not guessed (browsers cannot reliably tell). **Settings** > **Display** > **Mouse Wheel** set to **Zoom** makes a plain wheel zoom. It is saved per browser and applies to the detail and shared pages. On a dashboard a plain wheel scrolls the page (the diagram shows "Ctrl + scroll to zoom"); zoom with Ctrl/⌘ + wheel or a pinch. A middle, Alt + left or Space + left drag pans, and on the detail and shared pages a plain left drag does too (under 4 px it is a click). When the diagram is redrawn in the background, the view stays where it was.

### SpaceMouse

A 3Dconnexion SpaceMouse pans and zooms the diagram alongside the mouse (detail page, dashboards, shared pages). Push the cap sideways to pan, pull it up or press it down to zoom (about the cursor, or the centre when the cursor is off the diagram); Fit fits, and Shift, held, slows it down. On a dashboard the diagram under the cursor moves.

- Needs: Chrome or Edge (WebHID), and **the page opened over HTTPS** (or on localhost). Over plain HTTP the browser turns WebHID off, so it cannot work (the button at the bottom right says so). To serve the Server over HTTPS, see "Reverse Proxy & HTTPS" in [Installation](./installation.en.mdx).
- Connecting: press the joystick button at the bottom right of a diagram (on a dashboard it appears when the pointer is over the widget) and pick the device. Later visits connect on their own. A model without a serial number (the SpaceExplorer, for one) loses the browser's permission when unplugged: after plugging it back in, pick it with the button again.
- Linux: reading the device needs access to its hidraw node. Put this udev rule in place and apply it with `sudo udevadm control --reload && sudo udevadm trigger`; spacenavd can keep running.
```text
# /etc/udev/rules.d/70-spacemouse.rules
KERNEL=="hidraw*", ATTRS{idVendor}=="256f", TAG+="uaccess"
KERNEL=="hidraw*", ATTRS{idVendor}=="046d", ATTRS{idProduct}=="c603|c605|c606|c621|c623|c625|c626|c627|c628|c629|c62b", TAG+="uaccess"
```
- Windows / macOS: while 3Dconnexion's driver (3DxWare) holds the device, input may not arrive.
- Buttons work on the SpaceMouse Pro family, the SpaceExplorer and the two-button models (SpaceNavigator, Compact, ...); other models move with the cap only.
- Axis directions and speed are set per browser (in the developer console): `localStorage['shumoku.spacemouse.invert'] = 'x,y,z'` (the axes to flip), `localStorage['shumoku.spacemouse.speed'] = '1.5'` (a speed factor). Reload to apply.

## Linking Data Sources

In the topology **Settings** tab:

1. Add a **Metrics Source** (Zabbix or Prometheus) for real-time link utilization and node status
2. Add a **Topology Source** (NetBox) to auto-generate or merge topology data
3. Configure **Node Mapping** to associate topology nodes with monitored hosts

## Sharing

Click the **Share** button on any topology to generate a public link. Anyone with the link can view the topology without logging in.

To revoke access, delete the share token in the topology settings.

## Exporting

Use **Export** in the topology viewer to download the whole diagram as SVG or a
2x PNG, or as a standalone interactive HTML document. Server exports use the same
drawing engine and renderer as the viewer and CLI. Hierarchical sheets are gone:
nested groups are drawn together on one page.
