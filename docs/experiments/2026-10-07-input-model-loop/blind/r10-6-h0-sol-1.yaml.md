```yaml
groups:
  - id: server-room
    label: On-premises server room
  - id: aws-tokyo
    label: AWS Tokyo region
  - id: ap-northeast-1a
    parent: aws-tokyo
  - id: ap-northeast-1c
    parent: aws-tokyo

segments:
  - id: vlan-10
    vlan: 10
    prefix: 192.168.10.0/24
    addresses:
      fw-v: [192.168.10.2]
      app-1: [192.168.10.20]
  - id: sub-a
    prefix: 10.0.1.0/24
    group: ap-northeast-1a
    addresses:
      main: []
      web-c: [10.0.1.10]
  - id: sub-c
    prefix: 10.0.2.0/24
    group: ap-northeast-1c
    addresses:
      main: []
      db-c: [10.0.2.20]

redundancy:
  - id: prod
    label: vSphere HA cluster prod
    nodes: [hv-1, hv-2]

nodes:
  - id: rt-1
    type: router
    product: yamaha/rtx3510
    group: server-room
  - id: hv-1
    type: server
    product: dell/poweredge/r750
    software: VMware ESXi
    group: server-room
  - id: hv-2
    type: server
    product: dell/poweredge/r750
    software: VMware ESXi
    group: server-room
  - id: fw-v
    type: firewall
    product: palo-alto-networks/vm-series
    host: hv-1
    group: server-room
  - id: app-1
    type: vm
    software: Ubuntu
    host: prod
    group: server-room
  - id: main
    type: vpc
    product: aws/vpc
    prefix: 10.0.0.0/16
    group: aws-tokyo
  - id: web-c
    type: vm
    product: aws/ec2/t3.medium
    software: Amazon Linux
    group: ap-northeast-1a
  - id: db-c
    type: database
    product: aws/rds/mysql
    group: ap-northeast-1c
  - id: igw-1
    type: internet-gateway
    product: aws/vpc/internet-gateway
    group: aws-tokyo
  - id: tgw-1
    type: transit-gateway
    product: aws/transit-gateway
    group: aws-tokyo

links:
  - endpoints:
      - node: hv-1
      - node: rt-1
    speed: 10G
    segments: [vlan-10]
  - endpoints:
      - node: hv-2
      - node: rt-1
    speed: 10G
    segments: [vlan-10]
  - endpoints:
      - node: igw-1
      - node: main
    virtual: true
    description: Internet gateway attachment
  - endpoints:
      - node: tgw-1
      - node: main
    virtual: true
    segments: [sub-a, sub-c]
    description: VPC attachment through sub-a and sub-c
  - endpoints:
      - node: rt-1
      - node: tgw-1
    virtual: true
    description: Site-to-Site VPN IPsec tunnel 1
  - endpoints:
      - node: rt-1
      - node: tgw-1
    virtual: true
    description: Site-to-Site VPN IPsec tunnel 2
```

1. The two tunnels’ membership in one VPN connection is expressed in descriptions; the format has no structured link grouping.
2. I chose group IDs, type strings, product paths, and tunnel numbering. Cloud attachments are represented as virtual links.
3. Cloud attachment semantics are not explicit, particularly whether one attachment through two subnets should be one link carrying both segments. Also, the address comment permits a scalar, but the TypeScript type requires arrays; I used arrays.
